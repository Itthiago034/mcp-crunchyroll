# MCP Crunchyroll — BT3 Existing Authentication Map

## 1. Audit boundary

This map describes the repository at frozen BT2 commit
`ef05d3d4e1f577fcb28a908c3fdc33593c3f8b58`. It is evidence for BT3 Design
Gate 0, not a migration plan and not an implementation. No credential values
were loaded and no network path was executed during the audit.

The current authentication implementation is a legacy, caller-reachable path
split across `src/auth.ts`, `src/api.ts`, and `src/index.ts`. The BT1 transport
registry is intentionally disconnected from it: `PRODUCTION_OPERATIONS` is
empty and no public MCP handler reaches a transport backend or
`BrowserSessionManager`.

## 2. Persisted token model

`src/auth.ts` defines the following validated `TokenData` document.

| Field | Type and validation | Meaning | Classification |
|---|---|---|---|
| `access_token` | required non-empty string | bearer credential used by legacy API requests | A — SECRET |
| `refresh_token` | required non-empty string | credential used by the legacy refresh flow | A — SECRET |
| `expires_at` | required finite number in `1e12..1e16`, milliseconds since epoch by current use | access-token expiration | C — AUTH METADATA |
| `token_type` | required non-empty string | provider token scheme; currently used as stored metadata while requests construct `Bearer` explicitly | C — AUTH METADATA |
| `account_id` | required non-empty string | authenticated account identity | B — AUTH IDENTITY, NON-SECRET BUT SENSITIVE |
| `profile_id` | optional non-empty string | authenticated profile identity when supplied | B — AUTH IDENTITY, NON-SECRET BUT SENSITIVE |
| `unknown_fields` | optional, derived, non-enumerable list of field names only | diagnostic metadata; never persisted | C — AUTH METADATA |

`validateTokenData(unknown)` fails with `StorageError("CORRUPT_SESSION", …)`
for a malformed required field. Unknown top-level fields are tolerated on read,
reported by name only through a non-enumerable property, and removed on the
next save. Validation does not make an expiration decision; `isTokenExpired`
applies the current one-minute buffer.

The persisted representation is JSON at:

`~/.strider/crunchyroll/tokens.json`

The current secure-storage boundary requires the parent directories to be
owned by the effective UID and mode `0700`, and the target file to be a regular,
non-symlink file owned by the effective UID and mode `0600`. Reads use hardened
descriptor checks. Writes validate first and use a unique same-directory
temporary file, mode `0600`, full write, file `fsync`, close, and atomic rename.
The implementation does not claim directory-`fsync` durability.

## 3. Persisted session model

`src/auth.ts` separately defines `SessionInfo`.

| Field | Type and validation | Meaning | Classification |
|---|---|---|---|
| `email` | optional string containing `@` | login/account presentation identifier | B — AUTH IDENTITY, NON-SECRET BUT SENSITIVE |
| `username` | optional non-empty string | account presentation identifier | B — AUTH IDENTITY, NON-SECRET BUT SENSITIVE |
| `account_id` | optional non-empty string | account identity duplicated for session presentation | B — AUTH IDENTITY, NON-SECRET BUT SENSITIVE |
| `saved_at` | optional strict ISO-8601 timestamp; generated by `saveSessionInfo` | persistence timestamp | C — AUTH METADATA |
| `unknown_fields` | optional, derived, non-enumerable field-name list | diagnostic metadata; never persisted | C — AUTH METADATA |

The file is:

`~/.strider/crunchyroll/session.json`

It uses the same directory, ownership, mode, no-follow, hardened-read, and
atomic-write policy as `tokens.json`. The two documents are not written in one
filesystem transaction. A caller can therefore observe a valid token document
without a session document or vice versa; `TokenData.account_id` is the current
request identity source, while `SessionInfo` is presentation metadata.

## 4. Storage API and ownership

| API | Current behavior | Production callers |
|---|---|---|
| `getConfigDir()` | resolves `~/.strider/crunchyroll` | storage internals and tests |
| `validateTokenData()` | pure structural validation and sanitization | load/save paths, API response adapters, tests |
| `validateSessionInfo()` | pure structural validation and sanitization | load/save paths, tests |
| `saveTokens()` | validates, hardens directory/target, atomically replaces `tokens.json` | legacy login and refresh in `src/api.ts` |
| `loadTokens()` | hardened read; returns `null` only for genuine absence | legacy status and every authenticated legacy API call |
| `saveSessionInfo()` | generates one `saved_at`, validates, atomically replaces `session.json` | legacy login |
| `loadSessionInfo()` | hardened read; genuine absence is `null` | legacy status |
| `hasSavedTokens()` | hardened presence check; insecure state throws rather than appearing absent | legacy status |
| `clearAuthData()` | validates paths, classifies and removes token/session files, returns a non-throwing structured result | legacy logout and semantic `invalid_grant` handling |
| `isTokenExpired()` | `Date.now() >= expires_at - 60_000` | legacy status and authenticated request acquisition |

`clearAuthData()` owns the current logout result matrix. Its global states are
`CLEARED`, `ALREADY_ABSENT`, `PARTIAL`, and `FAILED`; each artifact is
`REMOVED`, `ALREADY_ABSENT`, or `FAILED`, with the closed failure reasons
`INSECURE_DIR`, `INSECURE_OWNER`, and `FILESYSTEM_ERROR`. It never follows or
unlinks through an insecure symlink. It is a persistence operation only: the
current repository has no process-local AuthContext to invalidate before the
asynchronous filesystem work begins.

## 5. Legacy acquisition, refresh, and request path

`src/api.ts` owns the current network-facing authentication behavior.

1. `getValidToken()` loads `tokens.json` for each authenticated legacy API
   call.
2. If absent, it throws a generic not-logged-in error.
3. If expired under the one-minute buffer, it calls `refreshRequest(tokens)`.
4. `refreshRequest` has one module-private process-local `refreshInFlight`
   promise. Concurrent callers share the same successful `TokenData` or the
   same secret-free `RefreshError`; the reference is cleared in `finally`.
5. Refresh posts the old refresh token to the legacy auth endpoint. A strict
   semantic `error === "invalid_grant"` invokes `clearAuthData` and returns
   `REAUTH_REQUIRED`. Transient, safe, and malformed failures preserve the old
   persisted document under the existing rules.
6. A successful response replaces the access token, optionally rotates the
   refresh token, recalculates `expires_at`, and persists the response's
   `account_id` and optional `profile_id`.
7. `request()` registers a raw access token with the active redaction scope,
   constructs `Authorization: Bearer <token>`, sends the request, and sanitizes
   an upstream error body before it can enter an Error message.

The refresh promise is single-flight only. It is not a generation, a lock over
all auth mutations, an AuthContext, or a stable token cache.

### Characterized identity replacement

Current tests deliberately prove that a successful refresh response carrying
a different `account_id` replaces the old account identity and that subsequent
legacy calls use the refreshed account in their URL. This is existing behavior,
not a safe continuity rule for BT3. BT3 Design Gate 0 therefore treats that test
as legacy characterization: the future transport AuthContext boundary will
reject an unexpected account/profile change during refresh, invalidate the old
context, and require an explicit authenticated-session installation. No current
legacy behavior is changed by this design gate.

## 6. Login, status, and logout reachability

`src/index.ts` exposes the current 21-tool MCP contract and calls APIs in
`src/api.ts` directly.

- `crunchyroll_login` passes caller email/password to the legacy `login()`
  flow, which contacts the legacy auth endpoint, validates its response, saves
  tokens, then saves session presentation data.
- `crunchyroll_status` calls `getStatus()`, which checks token presence, loads
  token/session files, and reports login/expiration state.
- `crunchyroll_logout` calls `logout()`, a passthrough to `clearAuthData()`.
- All existing content/account tools call their corresponding legacy API
  functions; those functions independently invoke `getValidToken()`.

BT3 must not migrate, alter, or newly expose any of these paths. Their cutover
belongs to later gates. The existing login implementation and live endpoints
were inspected as source only and were not executed.

## 7. Redaction boundary

`src/redact.ts` uses `AsyncLocalStorage` to give each MCP operation an isolated
set of runtime secret literals. `src/index.ts` creates the scope around a tool
call, registers sensitive caller fields (`password`, `access_token`, and
`refresh_token`), sanitizes successful content before leaving the scope, and
sanitizes errors at the boundary. Static patterns additionally remove common
Authorization, Bearer, Basic, password, refresh-token, and access-token forms.

Tests prove cleanup after success/failure, isolation between concurrent and
nested operations, literal registration semantics, output sanitization, and
the compiled/source MCP boundary. The registry is defense in depth, not a
secret store: it retains strings only for the active async operation and
clears them in `finally`. BT3 must register any access credential before a
future backend receives it and must never depend on a different operation's
scope.

## 8. Transport boundary at BT2

The BT1/BT2 transport types already separate caller policy from future auth
policy:

- `OperationDescriptor.callerParams` defines the only accepted caller keys.
- `OperationDescriptor.authDerivedParams` maps a path field to only
  `accountId` or `profileId`.
- Registry construction rejects overlap between those maps.
- `resolveCall` rejects caller-provided auth-derived keys as
  `CALLER_SUPPLIED_IDENTITY` before a backend is invoked.
- `ResolvedCall` contains only the captured descriptor and validated
  `callerParams`.
- `createTransportDispatcher` resolves synchronously and then awaits
  `backend.executeResolved(resolved)`, creating a future race boundary but no
  current auth binding.
- `PRODUCTION_OPERATIONS` is frozen empty.

The browser lifecycle modules are auth-agnostic. They own process/profile/CDP
lifecycle only and expose none of the token, session, account, profile, or
redaction storage APIs.

## 9. Complete datum classification

| Datum | Class | Permitted BT3 treatment |
|---|---|---|
| login password | A — SECRET | never accepted by AuthContext; legacy input only until a later login gate |
| access token | A — SECRET | private authority record only; never a public AuthContext field |
| refresh token | A — SECRET | remains with secure persistence/refresh producer; forbidden from AuthContext |
| Authorization header/value | A — SECRET | constructed only at the future backend use boundary; never caller input or metadata |
| cookie name/value or cookie jar | A — SECRET | no current type; BT3 forbids it and defers acquisition/ownership integration to BT4 |
| email | B — SENSITIVE AUTH IDENTITY | presentation storage only; forbidden from transport AuthContext |
| username | B — SENSITIVE AUTH IDENTITY | presentation storage only; forbidden from transport AuthContext |
| account id | B — SENSITIVE AUTH IDENTITY | private context record and narrowly resolved auth-derived parameter; no routine logs |
| profile id | B — SENSITIVE AUTH IDENTITY | optional private context record and narrowly resolved auth-derived parameter; no routine logs |
| expiration | C — AUTH METADATA | private context record; usable for fail-closed acquisition |
| `saved_at` | C — AUTH METADATA | persistence diagnostic only; not an AuthContext field |
| scope | C — AUTH METADATA | request/provider metadata; no current persisted field and no caller control |
| token type | C — AUTH METADATA | private validated material metadata; never a caller-selected header scheme |
| auth epoch | C — AUTH METADATA | process-local opaque identity; not public and not routinely logged |
| auth generation | C — AUTH METADATA | non-secret sequence metadata; may be logged without identity/secrets |
| context availability/staleness state | C — AUTH METADATA | safe fixed enum for diagnostics |
| tool name and declared public caller parameter | D — PUBLIC/NON-SENSITIVE unless the schema explicitly marks a credential | existing MCP contract |

## 10. Existing test seams relevant to BT3

- Auth/storage tests replace `HOME` with a temporary directory and use only
  synthetic token/session values.
- Refresh tests replace `globalThis.fetch`, assert exact requests, and prove
  single-flight success/failure and current identity replacement semantics.
- Transport tests use `FakeTransportBackend`, proving validation occurs before
  backend invocation and that backends receive `ResolvedCall`, not raw input.
- Redaction tests use sentinel strings and overlapping async scopes.
- MCP harness tests run both source and built bundle, compare exactly 21 names
  and baseline input schemas, and characterize unauthenticated behavior.
- Browser lifecycle fakes are separate and contain no auth seam; BT3 unit tests
  must not require a browser.

These seams are sufficient to implement deterministic BT3 unit tests without
real credentials, Crunchyroll traffic, browser launch, or a new dependency.
